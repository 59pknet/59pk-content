拿到代理 IP 的参数，很多人卡在配置这一步。设完上不了网，或者只有浏览器生效了，业务程序还是走直连。问题往往不在参数，在动手之前没想清楚一件事：到底想让哪些流量走代理。

全部软件都走，改系统设置。只想浏览器走，用浏览器插件。只想某个程序走，用客户端。写代码的，直接在代码里配。范围定下来，后面就是照着点几下。

![先定范围，再动手](https://oss.file.59pk.net/wp-content/uploads/2026/11/20261119093245469.webp/59pk)

## 先把四样东西准备好

正式配之前，先从服务商后台拿到四样东西：代理服务器地址（IP 或域名）、端口号、认证方式、协议类型。认证方式有两种，账号密码鉴权，或者 IP 白名单（终端授权模式），按服务商给你的来。协议类型一般是 HTTP、HTTPS、SOCKS5 这三种。

还有一句要先说清楚。代理 IP 是个网络技术工具，只能用在合法合规的业务场景里。非法翻墙、网络攻击、恶意爬虫、刷单诈骗这些，碰都别碰。

## Windows：图形界面就够了

系统级代理设好之后，大部分软件和浏览器都会全局走代理流量。Win10 和 Win11 的路子一样：

1. 按 Win+I 打开系统”设置”，进”网络和Internet”，点”代理”。 2. 找到手动设置代理，打开”使用代理服务器”。 3. 地址栏填服务商给的代理服务器地址，端口填对应的端口。 4. 如果本地内网不用走代理，在例外框里填 localhost;127.0.0.1;\*.local，多个地址用英文分号隔开。 5. 代理需要身份认证的话，第一次打开网页会弹出账号密码输入框，填进去就行。 6. 点”保存”，把浏览器关掉重新打开，就生效了。

老版本的 Windows 没有上面那个入口，走控制面板也一样：按 Win+R 输入 inetcpl.cpl 回车，打开”Internet 属性”，切到”连接”选项卡，点”局域网设置”，勾上”为LAN使用代理服务器”，填好地址和端口，再勾上”跳过本地地址的代理服务器”，一路点确定保存。

不想用了，回到代理设置页面，把”使用代理服务器”的开关关掉，保存，就恢复直连了。

不想动系统设置也行。像 [SSTap](https://www.59pk.net/183.html) 这样的客户端可以直接接 SOCKS5 代理，只管它自己的流量，系统其他软件不受影响。

## macOS：同一个入口，不同叫法

macOS 的步骤和 Windows 是一个意思，只是菜单名字不一样：

1. 点左上角苹果图标，进”系统设置”，点”网络”。 2. 选中当前正在用的网络，WiFi 或者以太网，点”详细信息”。 3. 切到”代理”标签页。 4. 按服务商的协议勾选对应项：Web 代理（HTTP）、安全 Web 代理（HTTPS）、SOCKS 代理。 5. 填代理服务器地址和端口。需要鉴权就勾上”代理服务器需要密码”，填用户名和密码。 6. 点”好”，再点”应用”，保存就生效了。

注意一点，Firefox 默认不读系统代理，要用代理得在浏览器里面单独配。

## 只想让浏览器走代理，装个插件就行

有些场景不希望整台电脑都走代理，只想浏览器里的网页走。这时候不用改系统设置，装个浏览器插件 SwitchyOmega 就行，微信、办公软件这些本地程序的网络一点不受影响：

1. 在浏览器应用商店里搜 SwitchyOmega，装上。 2. 打开插件选项，新建一个情景模式，名字随便起，比如”企业代理”。 3. 代理协议选 HTTP 或者 SOCKS5，填好代理地址、端口、账号密码。 4. 保存配置，点插件图标切换到这个情景模式，只有浏览器流量走代理。

## 代码里直接配，不用动系统设置

做数据采集、自动化业务的，大多不经过操作系统代理，直接在程序代码里配。Python 的 requests 这么写：

```
import requests
proxies = {
    "http": "http://username:password@代理地址:端口",
    "https": "http://username:password@代理地址:端口"
}
resp = requests.get("https://www.example.com", proxies=proxies)
print(resp.status_code)
```

Java 这样写：

```
System.setProperty("http.proxyHost", "代理地址");
System.setProperty("http.proxyPort", "端口");
System.setProperty("https.proxyHost", "代理地址");
System.setProperty("https.proxyPort", "端口");
```

服务器上没有图形界面，基本都是这条路，API、SDK、隧道代理接进去，不依赖操作系统设置。

## 出问题先查这四处

| 故障现象 | 排查方向 |
| --- | --- |
| 网页无法打开、连接超时 | 核对地址、端口是不是复制错了；检查本机防火墙、安全软件有没有拦截；确认账号余额、IP 白名单有没有加本机公网 IP |
| 弹出代理身份验证失败 | 确认账号密码没错；分清账号密码鉴权和 IP 白名单两种模式，别混着用 |
| 部分软件不走代理 | 有些应用不读系统代理，得在软件自己里面开代理配置，或者用 [Proxifier](https://www.59pk.net/242.html) 这类工具、代码 SDK 接入 |
| IP 被目标网站封禁 | 把请求频率降下来，换个 IP 类型；优先用高纯净度的 IP 资源池，拿到的 IP 先到[IP 检测工具](https://www.59pk.net/ipcheck)上测一下干不干净 |

## 动态、静态、隧道，看业务挑一个

动态 IP 代理，请求自动轮换出口 IP，用的是住宅或者移动 IP 资源，适合大规模数据采集、价格监控、广告验证，能降低反爬风险。静态 IP 代理，分配一个固定不变的 IP，独享 IP 资源，适合账号长期登录、舆情监测、固定身份访问的业务，IP 长期稳定不变。隧道代理，固定一个隧道入口，后台自动调度海量 IP，高并发长连接，适合高吞吐量的企业自动化业务，不用频繁去拿 IP 列表。挑哪种、怎么配，之前写过一篇[游戏代理 IP 怎么申请](https://www.59pk.net/221.html)，按那个思路来就行。

最后再提一句，工具合法不等于使用行为合法。代理 IP 改的是对外出口 IP，不是绝对匿名，服务商留着合规日志。挑服务商先看有没有《增值电信业务经营许可证》，来源不明的 IP 别用，黑产出来的 IP 沾上就是麻烦。
